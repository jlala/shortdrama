# 本地漫剧工作流执行规格 v0.3

更新：2026-10-15。用户要求先完成其他功能，会员问题后续处理。保留已有即梦执行器，增加独立的 `production.py` 本地制作脚本；使用Python标准库、FFmpeg/ffprobe和macOS临时语音，不增加数据库、Web服务或通用调度框架。

## 1. 制作与执行分工

创作者/Agent依据主需求设计故事、剧本、分镜和资产。程序检查镜头字段、管理真实文件、生成预演和粗剪，并保存每次输出的来源快照。分镜导出不伪装成自动剧本理解，媒体解码成功不代替人工观看和试听。

本地路径：分镜JSON → 导入首帧/音轨 → 分镜表和提示词 → 静态预演 → 导入并选用视频 → 多镜头粗剪 → 内部审阅包。

即梦路径：准备已选图片与真实参数 → save → quote → run → resume → select。成功返回和生成终态仍待会员账号实测；本轮本地制作不调用即梦或ComfyUI。

## 2. 文件结构

```text
项目目录/
  project.json       项目定位、示例标记、即梦授权与上限
  shots.json         分镜和生成参数、edit_order
  state.json         原平台操作、选用、本地素材和导入视频
  media/             按镜头版本保存的不可覆盖文件
  outputs/           即梦CLI下载文件
  exports/           每次分镜、预演、粗剪、打包的新目录
```

沿用输入schema_version 0.2和状态schema_version 1以兼容已有脚本；分镜字段、edit_order、assets和local_results是增量字段。state.json仍为单文件，所有写操作使用项目进程锁和原子文件替换。素材与分镜是独立文件，不宣称多文件数据库事务。

## 3. 分镜和版本

每个镜头至少说明用途、景别、主体动作、机位/运镜、图片提示词、视频提示词、剪辑目标时长和验收要点。接镜状态、音轨文本、字幕和剪辑入点可补充。

edit_order明确最终顺序与每个镜头的版本。未提供时用输入顺序，但遇到同一镜头多个版本必须明确选择。revise复制成新版本，保留原计划和选用，Agent随后修改并切换计划。

storyboard导出Markdown、CSV、提示词、SRT和输入快照。SRT按每镜头实际计划帧数累计，空字幕镜头仍占时；不做逐字强制对齐。CSV中的公式前缀按文本转义。

## 4. 导入与选用

import接受image/video/audio本地文件，先ffprobe探测并FFmpeg完整解码，再复制到项目、记录哈希与来源。媒体实际类型不符合请求时拒绝。镜头版本内已存在不同素材时要求新增版本，不覆盖旧版。

导入首帧更新references第一项并保留其余参考。已有平台操作或已导入视频的版本不能换参考。音轨独立于视频生成设置。网页视频保存在local_results，不编造resourceId、submitId或免费消费；外部费用明确unknown，不计为即梦CLI已结算费用。

select检查具体版本、生成参数/参考是否变化、媒体完整性，记录选用。已有CLI下载结果同样可进入本地检查与粗剪。新素材不自动替换选用。

## 5. 旁白、预演和粗剪

narrate使用已安装的macOS say音色生成临时语音，转换成48kHz双声道WAV后登记；不下载新音色、不调用付费TTS。重复相同文本/音色复用原文件；改变旁白创建新版本。其他系统可直接导入音轨。

preview取每镜头本地首帧，输出静态预演。rough-cut取显式选用视频，允许render_mode=still的镜头用静帧。按edit_order、edit_in_seconds和planned_edit_seconds顺序合成，统一尺寸、帧率、H.264/AAC；保持画幅并补边。缺镜头或视频过短时报错，不偷偷跳过、拉长或重复视频。

独立音轨替换该镜头原声，否则保留原声；无声镜头补静音。旁白超过计划时长时报错，需调整节奏。可添加循环背景音乐并调整音量。导出独立SRT供剪映精调，不烧录字幕。

输出检查包含完整解码、实际时长、尺寸、编码和哈希。render.json保存来源版本、文件哈希、实际媒体信息、生成来源/费用记录以及待人工审阅标记。每次新建导出目录；未完成的渲染没有成功manifest，不可打包成成功结果。

## 6. 批次与恢复

workflow.py的save/quote/run/resume增加--all，按edit_order串行处理，失败时停止并报告镜头。quote/run跳过已经提交、完成、失败或受理不确定的旧版本；resume只查有原submitId的任务。不会因重跑批次而重复付费生成。

原先费用和恢复约束继续生效：授权范围、最新报价和总积分上限；提交ID及预算占用先写盘；临时token只在内存；下载失败只下载；未知扣费不当零。多镜头不引入并发调度。

## 7. 交付与检查

package从已完成render.json生成内部审阅包，包含视频、字幕、分镜、提示词、输入、媒体来源与文件校验表。打包前核对视频、字幕和分镜文档；人工发布资料仍单独处理。

audit探测实际集文件并查重复、大小、逐集时长及漫剧首次上传/整剧1200秒总门槛，区分真人短剧与漫剧。依据用户提供的手册，不声明满足最新平台全部规则；内容、合同、权属、备案、AI声明和正式发布仍需创作者确认。

## 8. 验证状态

24项测试通过：14项原CLI及串行批次测试，10项本地制作测试，其中5项执行真实FFmpeg媒体。另已实际完成咖啡首帧导入、Tingting中文临时旁白和6秒720×1280静态预演。使用步骤见README。

仍待：即梦付费生成的真实保存/报价/运行/资源终态；作品级的叙事、动态与正式声音审阅；渠道签约和发布。ComfyUI仅完成方案比较，未实施模型部署或付费服务接入。
