# 即梦网页功能与 CLI 逐项核验

核验日期：2026-10-31（Asia/Shanghai）。

核验对象：本项目 `.tools/bin/dreamina-canvas`，实测版本 **1.2.0**，commit `cee4f27a`，public / cn 发行版。结论只适用于本次读取的版本和服务目录。

## 结论与证据范围

CLI 覆盖基础素材生成、主体引用、有限的时间轴编排，以及较完整的导演台数据操作与本地渲染。网页的短剧角色／场景管理、工具箱和多种专用编辑工具，没有完整的一对一 CLI 接口。

本报告共有 **115 条对应记录**：37 条直接对应、38 条部分对应、35 条未发现专用入口、3 条网页界面交互、2 条待确认。记录按网页功能位置展开，不代表 115 个互不重复的底层接口；“直接对应”也不等于全部完成了端到端执行。

尤其需要区分：

1. **短剧工作室画布与 CLI 画布的项目标识尚未建立对应。** 浏览器中的短剧页面使用数字 ID；本次 CLI 列出的画布使用 UUID。数字项目 ID 被 CLI 本地参数校验拒绝，不能直接代入。是否另有映射或迁移入口仍待平台说明，不能据此断言两套系统永久不互通。
2. **CLI 的 timeline 不等于网页完整多轨编辑器。** 已找到画面顺序、音频片段、裁切、速度与音量参数；未发现字幕轨、字幕样式、任意多音轨混音或通用时间轴成片导出的明确入口。
3. **导演台 MP4 导出已经本地实测成功。** 这是 3D 参考场景的渲染，不是把任意生成素材时间轴导出为成片。
4. **存在命令不等于已验证生成效果。** 本轮没有提交付费生成、后编辑或样片转正，也没有保存云端节点或导演台修改。云端导演台复查版本、草稿版本及正文均与核验前一致。

### 分类含义

| 分类 | 含义 |
|---|---|
| 直接 | 有明确对应命令或字段；是否实测成功另看证据列 |
| 部分 | 只能覆盖部分行为，或需用通用生成／数据编排近似实现 |
| 未发现 | 当前 schema、帮助、目录中未发现专用入口，不推断其他版本或私有接口情况 |
| 待确认 | 有通用数据结构，但不足以确认网页功能的完整调用方法 |
| 界面 | 属于网页的交互、视图或快捷键；CLI 可以提供数据操作，但不复现这类交互 |

## 九、CLI 另有的能力与参数差异

- 当前目录提供样片模型及 `node promote video-sample` 转正入口；存在对应命令不代表本轮已执行转正。
- `node interpolate video --fps 30/60` 提供补帧入口，本地参数检查通过，未提交处理。
- `director` 支持 FBX 动作导入／导出，区别于一般 3D 几何模型上传。
- 图像／视频超清、抠图和补帧命令**直接提交处理，不依赖 `--run`**。本轮只运行其已声明无副作用的 `--dry-run` 检查。
- 旧资料中“只有首帧必须用 m2v”已不适用：当前 `first_last_frame` 明确接受一张首帧图。模型目录中同名模式可能分别描述单帧与双帧约束，不能把其中一项覆盖另一项。
- 当前 TTS 可以显式指定模型和 scenario。旧版“不传 model”的说明仅覆盖未指定模型的音色配音入口，不是所有 TTS 的通用限制。
- 实时音频目录在 `text-reading` 下列有音频参考范围，但当前 CLI 的 schema／调用限制仅允许 `omni-dubbing` 使用 `--ref`。本地反例检查返回 `CLI_FIELD_FORBIDDEN`，因此朗读入口不能依据目录独自添加引用。
- `node find` 才是本版的节点搜索命令，未发现 `node list`。配套文字指引中个别恢复示例与本版命令名有差异时，以二进制为准。

## 十一、对项目执行方式的影响

1. 素材生成、引用、任务恢复和资源下载，可以继续以画布 CLI 为主要入口，并按实时模型规格执行。
2. 复杂空间与运动参考可使用 CLI 导演台；已有画布导演台能够读取，本机具备实际渲染条件。本轮没有验证云端写入与回传，因此后续首次保存仍要核对保存回执与读回结果。
3. 新短剧工作室数字 ID 项目，先在网页端操作或取得明确映射；不能把 UUID CLI 命令强行套上去。
4. 工具箱、角色库、完整场景档案、局部编辑及字幕工具，按网页实际界面操作；不要仅靠通用生成提示词宣称已经执行相同工具。
5. 多音轨混音、字幕与成片交付继续使用已经验证的本地后期或剪映流程。只有基础序列且满足限制时，再考虑 CLI timeline。
6. 需要对生成或后编辑做真实验证时，以具体镜头、素材、报价和已有授权安排；本报告没有把未执行项标为成功。

### 用户确认的人工衔接方式

用户已明确：CLI 中没有的功能，可以在实际制作时由用户手动操作网页。

执行时，Agent 先准备素材、文案及参数，并交代目标项目／节点、入口、步骤、预期结果与回传方式；相关人工步骤尽量集中交接。等待期间继续推进独立工作。用户完成后核对节点、资源或导出文件，保存版本与选用记录，再衔接后续流程。无需每次重新确认是否允许采用这一协作方式；实际付费操作仍沿用具体项目已有的授权范围。
